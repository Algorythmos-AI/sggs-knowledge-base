## Check 3 — Sihari Sanity

Note: The initial regex approach (`(^| )ਿ`) generated false positives because Gurmukhi sihari is stored post-consonant in Unicode (visual-order vs. logical-order). The codepoint-level check is the correct method.

## Check 5 — Raag Boundary Check

### Distinct raag values and spans

| raag | Min Ang | Max Ang | Rows |
|------|---------|---------|------|
| null (`None`) | 1 | 8 | 385 |
| ਆਸਾ | 8 | 360 | 758 |

| ਗਉੜੀ | 12 | 347 | 9,617 |
| ਧਨਾਸਰੀ | 13 | 13 | 14 |
| ਸਿਰੀਰਾਗੁ | 14 | 94 | 3,170 |
| ਮਾਝ | 94 | 151 | 2,518 |

### Issues

**Issue A — Unexpected raags ਗੂਜਰੀ and ਧਨਾਸਰੀ in Angs 1–13:**

- **ਗੂਜਰੀ** (22 rows, Ang 10): These rows belong to the *So Purakh* liturgical section (Angs 10–12). They are tagged with ਗੂਜਰੀ raag — which is canonically correct for So Purakh (it is in Raag Gujri M4). However, the QA spec expected only the four main raags in 14–360. These pre-raag liturgical compositions legitimately carry their own raag label. This is a **schema design decision**, not a data corruption.
- **ਧਨਾਸਰੀ** (14 rows, Ang 13): Ang 13 is Aartee Sohila in Raag Dhanasri M1. Again canonically correct liturgically. Same schema note applies.

**Issue B — ਆਸਾ and ਗਉੜੀ appear before expected starts:**

- **ਆਸਾ** min Ang = 8 (expected ~347): Ang 8–12 is *So Daru* (section header `ਸੋ ਦਰੁ`) which is in Raag Asa M1 — this is correct per the SGGS. The corpus's raag field reflects the actual raag of each composition, not just where the Raag-section begins. The Asa raag section (Angs 347+) is the *bulk* canonical section; the early ਆਸਾ rows are pre-raag liturgical compositions that happen to be in Raag Asa.
- **ਗਉੜੀ** min Ang = 12 (expected ~151): Same pattern — Sohila (Ang 12) has compositions in Raag Gauri Deepki M1 and Raag Dhanasri.

**Conclusion:** The raag field is composition-level (correct by canonical authority), not section-header-level. The QA spec's assumption that a given raag appears only within its named section is incorrect for the pre-raag liturgical pages (Angs 1–13). No data corruption is present. However, **2 raag values (ਗੂਜਰੀ, ਧਨਾਸਰੀ) are not in the spec's allowed list**, and the raag boundary transitions happen earlier than specified — this is a **schema documentation gap**, not an error.

**Result: FAIL on boundary spec, but findings are liturgically valid. Recommend updating the allowed-raag list to include ਗੂਜਰੀ and ਧਨਾਸਰੀ for Angs 1–13.**

## Top 3 Most Serious Issues

### Issue 1 — CRITICAL: Timestamp contamination in `text` field (Check 2)
**9 rows** in Angs 262, 281, 285, 290, 296, 347, 353, 359, 360 contain embedded `HH:MM:SS` strings mid-Gurbani-text. This is the only genuine data corruption found. The text field is broken for these lines — any substring search, NLP, or display of these lines will surface corrupted text. IDs: 11594, 12717, 12958, 13258, 13606, 15880, 16171, 16449, 16484.

### Issue 2 — MODERATE: Undocumented raags ਗੂਜਰੀ and ਧਨਾਸਰੀ in Angs 10–13 (Check 5)
The QA spec's allowed-raag list for Angs 14–360 omits two legitimate raags that appear in the pre-raag liturgical section (Angs 1–13). The data is canonically correct but the schema documentation / allowed-raag enumeration is incomplete. Downstream consumers filtering by raag may miss or mishandle these 36 rows.

### Issue 3 — LOW: Ang 12 spot-check targets fall on Ang 13 (Check 8)
Lines from Sohila (`ਅਨਦਿਨੋ`, `ਸਹਸ ਤਵ ਨੈਨ`) expected at Ang 12 are assigned Ang 13 in the corpus. Content is present and correct; the ±1 Ang discrepancy likely reflects a difference between the expected PDF page boundary and the corpus's Ang assignment. Low severity — data is present.

## Notes for Corpus Maintainer

1. **Timestamp strip:** For IDs 11594, 12717, 12958, 13258, 13606, 15880, 16171, 16449, 16484 — remove the `HH:MM:SS` substring (and surrounding spaces) from the `text` field. The Gurmukhi text before/after the timestamp is otherwise intact.
2. **Schema update:** Add `ਗੂਜਰੀ` and `ਧਨਾਸਰੀ` to the allowed-raag enumeration with the note that they appear only in the pre-raag liturgical section (Angs 1–13).
3. **Section field:** The `section` field value `ਜਪੁ` is used for the vast majority of rows (13,845 of 16,484). This appears to be a default/placeholder rather than a meaningful section discriminator for compositions outside the actual Japji. Recommend reviewing the section-assignment logic.
